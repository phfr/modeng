## Step 1. Eight assumptions of transfer LightGBM and the baselines, and what follows if each is false

| # | Assumption | If it is false |
|---|---|---|
| A1 | **A gene is its identity.** Transfer scores a gene through its column in the disease x gene matrix; a gene with an empty column has no representation (B3: 0.4 % found). | If a gene can be represented by content (sequence, expression, perturbation response, the company it keeps in omics tables), the empty column can be imputed and the same transfer machinery reaches zero-support genes (ML-1, ML-3). |
| A2 | **Donor diseases are chosen by overlap of current seeds.** With 3-5 seeds the overlap estimate is nearly noise. | If disease similarity can be learned from non-gene information (name, ontology, phenotype text) and trained to predict *future* overlap, few-seed diseases get good donors (ML-8). |
| A3 | **The label matrix at the seed date is a clean sample of the truth.** In fact it is an ascertained sample: popularity-driven, ontology-propagated, with identifier and re-scoring artefacts (B5, B6). | If the observation process is modelled explicitly, a model can infer the latent module instead of imitating the curation process, and "unknown to any disease" becomes "not yet looked at" rather than "negative" (ML-2). |
| A4 | **One pointwise model for all diseases; per-gene scores are independent.** LightGBM scores each (disease, gene) row on its own. | If the task is set-valued (the seeds as a set say which modality matters; the output is a module with a size), an in-context / set model can adapt per disease without retraining and can output a calibrated set (ML-5, ML-6, ML-7). |
| A5 | **Static membership is the training target.** The model learns "what a known disease gene looks like", but the test asks "what arrives next". | If arrivals differ systematically from incumbents (B4: 57 % GWAS-only, 82 % of strictly new), training on arrival events and on evidence trajectories is the right objective (ML-6, ML-9). |
| A6 | **GWAS arrival is unpredictable beyond own-trait sub-threshold z.** Each trait's weak signal is read alone. | B4 says arrival is mainly a statistical-power event. Then it is a denoising problem with paired training data (small-N release, large-N release of the same trait), learnable across traits (ML-4). |
| A7 | **Curated resources (PPI, GO, KG) are the gene-gene information.** All of them are biased to studied genes; B2 shows they add ~0 beyond degree. | If uncurated, high-coverage co-occurrence data exist (gene lists in paper supplements, perturbation signatures), they cover understudied genes that curated resources miss (ML-3). |
| A8 | **Features help uniformly, so they are judged by the average gain.** modet rejected feature families on overall nuAP (+0.000-0.007, B2). | If the gain is concentrated in a stratum that the average hides (zero-support genes are a minority of top-100 hits), the right test is stratum-specific, and the right architecture gates content against transfer per gene, by support (ML-1, ML-5). |

## Step 2. Ideas

Conventions for the minimal tests: python = `~/biotools/venvs/bio-net/bin/python`; a method is `score(tasks, B) -> [n_tasks, n_genes]`
registered in `src/modeng/methods/__init__.py`; every task uses `B.context_for(task)` (ontology-relative masking, TASKS); GPU jobs through
`~/biotools/bin/gpu-run --mem <GB> -- <cmd>`. Sealed diseases never enter (they are already removed by `data.excluded_task_ids()`, TASKS).
"Stratum Z" = positives with zero transfer support; "stratum G" = GWAS-only positives (from `groundtruth/arrival_*.parquet`, file listed, schema
not opened). Every test reports nuAP, AP and the top-100 recall in strata Z and G next to `transfer_jaccard` on the same dev tasks.

### ML-1 — Cold-start donor imputation: content-predicted association profiles
- **Mechanism.** Factorise the seed-date disease x gene matrix (rank ~256), then train a content encoder (ESM C + GTEx + GO/Reactome T0 + DepMap + Perturb-seq signatures) to regress a gene's latent factor, with DropoutNet-style training (randomly hide the gene's own column so the encoder must work from content). At test time every gene with an empty or thin column gets its *predicted* association profile, and the unchanged transfer scorer runs on the completed matrix, with a gate that trusts imputation in proportion to how little real support the gene has.
- **p_typical:** 0.12
- **Data.** On disk: `modet/data/processed/features/{esmc,gtex_v8,go_t0,reactome_t0}.parquet`, subex derived DepMap 20Q4 and Perturb-seq matrices (INV); label matrices in `modeng/data/cache/labels_*.npz`. No download.
- **Leakage class:** temporal-clean on `temporal` if only T0 features are used (ESM C, GTEx v8, GO/Reactome T0, DepMap 20Q4/21Q1, Replogle; the 2025 CD4 and Nadig Perturb-seq sets make it transductive). Main route: GO annotations or perturbation data produced *because* of a post-2021 disease finding; use the T0 GO file only.
- **Minimal test (~40 min, CPU or 4 GB GPU).** (1) `TruncatedSVD(256)` on the masked 21.04 context; (2) MLP/ridge content -> factor, 5-fold over genes with the gene's column dropped, report held-out-gene AUROC for membership; (3) `score = transfer(context + lambda(support) * imputed)`; register as `ml1_coldstart`; run dev split of `temporal`, then `holdout`. Inputs: the four feature parquets + DepMap matrix.
- **Expected effect.** Overall nuAP +0.005 to +0.015 over transfer (most positives are already supported, B3); AP ~0. The claim is stratum Z: top-100 recall from 0.4 % to 2-4 %. Why: the column is the only thing missing for these genes, and nuAP weights low-degree genes, which are over-represented in stratum Z.
- **Kill rule.** Held-out-gene membership AUROC of the encoder < 0.65 (B3 gives 0.60-0.63 for the best existing method inside the unknown pool), or stratum-Z recall@100 < 1.5 % on dev, or overall nuAP drops by > 0.005.
- **Most likely failure.** Content does not predict disease profile beyond what gene covariates already give: modet's PoPS-like ridge on 57k features added at most +0.007 (B2). Imputed profiles then regress to the popularity mean and only reshuffle hubs.

### ML-2 — Ascertainment-simulator prior-fitted network
- **Mechanism.** Write a generative simulator of *how a disease gene set comes to be observed*: draw a latent module (mixture of a few compact regions in gene-content space plus a polygenic GWAS-like tail), then pass it through an observation process with known knobs (discovery probability rising with gene popularity, ontology propagation from children, evidence-type mix, a "power" dial that grows between two dates). Train a transformer on millions of simulated (observed set at t0, observed set at t1, latent module) episodes, TabPFN-style, so that at test time it amortises the posterior over the latent module given the real seeds: no real future labels are needed for training. Simulator knobs are fitted to pre-T0 statistics only (19.04 -> 21.04 diffs).
- **p_typical:** 0.04
- **Data.** On disk: 19.04 and 21.04 label sets (`groundtruth/ot_t19_sets.parquet`, `ot_t0_sets.parquet`), gene covariates (`covariates/allgene_t0_string115_phys_notm_400.parquet`), content embeddings as in ML-1. No download.
- **Leakage class:** temporal-clean (the cleanest idea here: training data are synthetic, knobs fitted before T0). Main route: tuning simulator knobs on dev-split results of the 21.04 -> 25.09 benchmark; fix the knobs from 19.04 -> 21.04 and pre-register them.
- **Minimal test (~2 h, 12 GB GPU).** (1) Fit 6 knobs (popularity exponent, propagation rate, tail fraction, module count, module width, power growth) by matching 19.04 -> 21.04 arrival statistics; (2) generate 200k episodes over the real 19,255-gene content space; (3) train a 6-layer set transformer (seed tokens = content embedding + observed-popularity features, candidate tokens cross-attend to seeds), `gpu-run --mem 12 -- python scripts/ml2_pfn.py`; (4) score dev tasks, alone and as a rank-average with transfer.
- **Expected effect.** Alone: nuAP 0.03-0.06 (below transfer, because it ignores the donor matrix). Combined with transfer: +0.005 to +0.02 nuAP, AP flat or slightly down (it deliberately discounts popularity). The value is that the posterior is defined for never-observed genes, and that the sim-to-real gap is itself a measurement of which knobs describe disease gene discovery.
- **Kill rule.** Combined gain < +0.005 nuAP on dev *and* stratum-Z recall@100 < 1 %; or the PFN alone is below `rwr_string` on dev.
- **Most likely failure.** Sim-to-real gap: real modules are not compact in any content space we have (B2 says network locality is weak), so the prior is wrong and the posterior is confident nonsense.

### ML-3 — Gene-set language model on dated supplement-table gene sets
- **Mechanism.** Pretrain a masked set model on the ~640-790k gene sets that Rummagene mined from PMC supplementary tables (differential-expression lists, screen hits, proteomics tables), keeping only papers published before the seed date. The resulting embeddings encode "which genes working biologists list together", a co-occurrence source that covers understudied genes because omics tables are unbiased by curation, unlike PPI/GO/KG (B2). Use it two ways: as the content space for ML-1/ML-5, and directly as a set-completion scorer conditioned on the seeds.
- **p_typical:** 0.07
- **Data.** Download: Rummagene gene-set file from https://rummagene.com (download page; paper reports 642,389 sets from 121,237 articles, the lab page now 793,703 sets from 147,611 articles; expected size about 1-2 GB uncompressed, size and exact file URL not verified). Needs PMCID -> publication date (PMC OA file list, ~500 MB, https://ftp.ncbi.nlm.nih.gov/pub/pmc/oa_file_list.csv, URL from memory, not verified).
- **Leakage class:** temporal-clean on `temporal` if sets are filtered to papers dated <= 2021-04; clean on `forward` with a <= 2025-09 filter; holdout-current otherwise. Main route: supplement tables of the very GWAS / exome papers that create the future labels (a table of "genes at significant loci" is the label itself). The date filter removes this; additionally drop sets from papers that are cited as evidence in `ot_evidence/evidence_2509` literature fields.
- **Minimal test (~1.5 h, CPU + 8 GB GPU).** (1) Parse the GMT, date-filter, keep sets of 5-2000 human genes; (2) baseline first: PPMI + SVD(256) gene embedding from the set-gene incidence matrix (10 min, CPU), score = mean cosine to seeds; (3) then a small masked-set transformer for 30 min, `gpu-run --mem 8 -- python scripts/ml3_setlm.py`; (4) dev split, three numbers: alone, plugged into ML-1 as the content encoder, rank-averaged with transfer.
- **Expected effect.** Alone nuAP 0.03-0.07; with transfer +0.005 to +0.02 nuAP, AP +0 to +0.01. Stratum Z recall@100 to 2-5 %. Why: it is the only source here where a gene unknown to every disease database still has thousands of informative contexts.
- **Kill rule.** Coverage check first: if fewer than 70 % of stratum-Z positives appear in >= 20 pre-T0 sets, stop. Otherwise kill if the SVD baseline plus transfer gains < +0.005 nuAP and stratum-Z recall@100 < 1.5 %.
- **Most likely failure.** The embedding re-learns popularity and tissue expression (most supplement sets are DE lists), which modet already showed adds ~0 (GTEx/HPA, B2); the date filter also removes about half of the corpus.

### ML-4 — Biobank release-pair power extrapolator for GWAS arrivals
- **Mechanism.** B4 says GWAS-only arrivals are mainly a power event and that own-trait sub-threshold z already has AUC ~0.8. So learn the map "small-N gene-z landscape -> genes significant at large N" from *paired releases of the same trait* across many traits (FinnGen R4 at ~177k samples vs R12 at ~500k; on disk, the T0 vs post-T0 MAGMA runs), with a model that reads the gene's own z, its locus neighbours' z, the z of the same gene in genetically correlated traits, and gene constraint. Applied to a task disease, it turns T0 summary statistics into a calibrated probability of later significance per gene, which is exactly stratum G.
- **p_typical:** 0.08 (using sub-threshold z as a feature is ~0.7; supervised training on release pairs across traits is the rare part)
- **Data.** On disk: `modet/data/processed/gwas_magma_t0/` (112 GCST studies with `_w0`, `_w10`, `_leads` parquets; one inspected file has 8,200 genes x 10 columns incl. z, p) and `gwas_magma/` (102 EFO-named post-T0 parquets), `neale_rg` (INV). Download for the full version: FinnGen R4 and R12 summary statistics (R4: 2,444 core endpoints, public Q4 2020; R12: 2,469 core endpoints, 520k samples; several hundred GB for all endpoints, so start with ~150 endpoints, ~60 GB; access is through a registration form that asks for an e-mail address, so the user has to request it).
- **Leakage class:** on `temporal`: features are temporal-clean (T0 sumstats), but the *extrapolator's training labels* are post-T0 releases of other traits, so the result is **transductive** unless training pairs are restricted to pairs fully before T0 (e.g. GWAS catalog study pairs of the same trait both published <= 2021-04; R4 itself is the only clean FinnGen release). On `forward`: clean with any release <= 2025-09. Main route: a training trait that is the task disease, its ontology relative, or a strongly correlated trait; exclude by EFO relatives and by |rg| > 0.8.
- **Minimal test (~1.5 h, CPU).** On-disk only. (1) Match T0 studies to post-T0 EFO files via `gwas_magma/studies_selected*.tsv` and `t0_coverage.tsv` (listed, not opened); (2) rows = (trait, gene), features = T0 z, max z within +-500 kb, z rank, mean z of the gene in the 5 most correlated T0 traits, gnomAD constraint, gene length; label = post-T0 MAGMA p < 2.5e-6 and not T0-significant; (3) LightGBM, leave-trait-family-out; (4) score tasks that have a T0 study, zero elsewhere, rank-average with transfer; evaluate on `temporal` dev restricted to covered diseases and on stratum G.
- **Expected effect.** On covered diseases: stratum-G recall@100 from 16 % to 25-30 %, nuAP +0.02 to +0.04; diluted over all dev diseases +0.005 to +0.015 depending on coverage. AP +0.01 on covered diseases.
- **Kill rule.** Leave-trait-out AUC of the extrapolator not above own-trait z alone by >= 0.03 (i.e. < ~0.83 where raw z gives ~0.80), or fewer than 15 dev diseases covered.
- **Most likely failure.** Coverage: B4's AUC came from 4 diseases, and "T0 UKB MAGMA studies as donors" already failed in modet (banned list), so cross-trait borrowing may add nothing to own-trait z; also MAGMA gene z is not the L2G evidence that Open Targets uses, so the "significant later" label and the benchmark label differ.

### ML-5 — Identity-blind episodic set-completion transformer, many set families
- **Mechanism.** Meta-train one transformer on episodes "given k members of a gene set, rank the rest", drawn from many set families at the seed date (disease rows, GO terms, Reactome pathways, MSigDB, CORUM complexes, HPO phenotypes, Perturb-seq clusters, top-MAGMA genes per T0 trait). Gene tokens carry only frozen content embeddings plus a support-count feature, never a learned identity embedding, and whole genes are held out during training, so "a gene the model has never seen in any set" is the training distribution rather than the exception. Seeds attend to each other, so the model can infer per disease which modality the module lives in.
- **p_typical:** 0.35 (set transformer over seeds is common; identity-blind tokens with gene-level holdout and non-disease set families is less so)
- **Data.** On disk: `msigdb_v7.4`, `corum_v3_0`, `hpo_annotations_2021-01_wayback`, GO/Reactome T0 features, subex Perturb-seq derived matrices, `gwas_magma_t0` (INV). Optional download for a text channel: GenePT embeddings, https://zenodo.org/records/10833191, 574 MB (gene summaries as of 2024, so transductive on `temporal`, clean on `forward`).
- **Leakage class:** temporal-clean with T0 set families; transductive if GenePT or current GO is used on `temporal`. Main route: pathway/HPO sets that were defined from disease findings (HPO phenotype-gene sets are close to disease-gene labels; use only the 2021-01 snapshot and mask sets whose Jaccard with the task's seeds+targets is >= 0.5, the same rule the harness uses for near-duplicates, TASKS).
- **Minimal test (~2 h, 16 GB GPU).** (1) Build ~30k T0 sets of size 5-500; (2) 4-layer set encoder over up to 64 seeds, candidate scoring by cross-attention, sampled-softmax loss with degree-matched negatives, 20 % of genes held out entirely; `gpu-run --mem 16 -- python scripts/ml5_episodic.py`; (3) report held-out-gene vs seen-gene AUROC on held-out GO/disease sets (the generalisation gap is the key diagnostic); (4) dev tasks alone and with the transfer score as an extra candidate feature.
- **Expected effect.** Alone nuAP 0.05-0.09; with transfer as input +0.01 to +0.02 nuAP over the transfer baseline, AP +0 to +0.01; stratum Z recall@100 to 2-3 %.
- **Kill rule.** Held-out-gene AUROC on disease episodes < 0.65, or combined gain < +0.005 nuAP on dev.
- **Most likely failure.** "GNN = MLP" (B2) generalises: with median ~11 seeds (B6) the set context carries little beyond the mean seed embedding, and the model collapses to a content-similarity scorer that modet already found weak.

### ML-6 — Tabular in-context learner with neighbour-disease arrivals as context
- **Mechanism.** Treat each disease as a small tabular task solved in context by a pretrained tabular foundation model (TabICL / TabPFN-class), with no per-task gradient training. The context rows are not the disease's own seeds (they say what incumbents look like) but (gene, features, label = arrived 19.04 -> 21.04) rows from the task's k nearest donor diseases, so the model learns in context what an *arrival* looks like for this disease family and applies it to the task's candidates.
- **p_typical:** 0.30 (plain "use TabPFN on gene features" ~0.45; arrival rows of neighbours as the context is rarer)
- **Data.** On disk: 19.04 and 21.04 sets, covariates, transfer features computed by the harness. Model weights: TabICL (open weights, https://github.com/soda-inria/tabicl; reported to handle 500k context rows), a few hundred MB.
- **Leakage class:** temporal-clean (context labels are 19.04 -> 21.04 arrivals, all before T0). Main route: using 21.04 -> 25.09 arrivals of neighbour diseases as context, which would hand over the task's own targets through ontology relatives; forbidden on `temporal`, allowed on `forward` with 21.04 -> 25.09 context.
- **Minimal test (~1 h, 8 GB GPU).** (1) Per (disease, gene) feature vector of ~40 columns: transfer scores computed on 19.04 for context rows and on 21.04 for query rows, degree, constraint, T0 MAGMA z where available, 16 content PCs; (2) per task: context = arrivals + 20x sampled non-arrivals from the 20 nearest donors (~20k rows), query = pre-filtered top 3,000 candidates by transfer plus all zero-support genes in a second pass; `gpu-run --mem 8 -- python scripts/ml6_tabicl.py`; (3) compare with a LightGBM trained on the same pooled arrival rows (this separates "arrival objective" from "in-context model").
- **Expected effect.** +0.005 to +0.015 nuAP over transfer LightGBM, AP about flat. Most of the gain, if any, will come from the arrival objective (A5), and the LightGBM control will show that.
- **Kill rule.** In-context model not better than the pooled-arrival LightGBM control by >= 0.005 nuAP, or neither beats the baseline by >= 0.005.
- **Most likely failure.** 19.04 -> 21.04 arrivals are dominated by the label artefacts of B5 (re-attached old evidence, identifier migration), so the context teaches the model the curation pipeline of that period rather than discovery.

### ML-7 — Masked discrete diffusion over gene sets: the module as a sample
- **Mechanism.** Train an absorbing-state (mask) discrete diffusion model over gene sets in the identity-blind token space of ML-5, conditioned on a disease encoding, and generate modules by inpainting around the seeds. Many samples per disease give three outputs that a ranker cannot: marginal inclusion frequency (the ranking), the distribution of set size (a cutoff with calibration), and the co-inclusion matrix across samples (internal structure: sub-modules are genes that enter together).
- **p_typical:** 0.15
- **Data.** Same as ML-5; no download.
- **Leakage class:** temporal-clean with T0 set families (as ML-5). Main route: same as ML-5; additionally the size prior must be fitted on 19.04 -> 21.04 growth, not on 25.09 sizes.
- **Minimal test (~2 h, 16 GB GPU).** Reuse the ML-5 encoder; add the mask-diffusion objective (random mask rate per episode instead of a fixed k); 64 samples per dev task by iterative unmasking over the top 2,000 candidates; `gpu-run --mem 16 -- python scripts/ml7_setdiff.py`. Report (a) ranking metrics from inclusion frequency, (b) calibration: predicted number of arrivals vs observed per disease (Spearman and ratio), (c) agreement of co-inclusion clusters with subex's annotation-Leiden decomposition (banned list says that is the confirmed best decomposition).
- **Expected effect.** Ranking equal to ML-5 within +-0.005 nuAP (the marginals are the same model). The gain is the second deliverable of the brief, "output the module itself": predicted vs observed arrival counts with Spearman >= 0.4 across dev diseases.
- **Kill rule.** Ranking worse than ML-5 by > 0.005 nuAP, or size calibration Spearman < 0.3, or co-inclusion clusters no better than chance against the annotation decomposition.
- **Most likely failure.** With ~20-30 positives per disease (B6) among 19,255 genes, joint structure is not identifiable; samples are independent draws from the marginals and the "structure" is noise.

### ML-8 — Disease encoder trained to predict future gene overlap
- **Mechanism.** Replace seed-overlap donor selection with a learned disease encoder (name and definition text embedding, ontology position, HPO phenotypes, current gene-set summary) trained contrastively so that similarity predicts the overlap of two diseases' *later* gene arrivals, using 19.04 -> 21.04 as supervision. Transfer then weights donors by this similarity, which matters most where seed overlap is undefined or noisy: diseases with 3-5 seeds.
- **p_typical:** 0.30
- **Data.** On disk: ontologies (`modeng/data/cache/onto_*.parquet`), disease names, HPO 2021-01, label sets 19.04/21.04. Text encoder: any open sentence-embedding model run locally on disease names and definitions (~1 GB weights); definitions come from the 21.04 disease index (`/mnt/msadb/modet/downloads/ot2104`, listed in INV, content not opened).
- **Leakage class:** temporal-clean if the text encoder is frozen and only reads 21.04 disease text. A pretrained language model has seen post-2021 literature, so strictly this is a mild **transductive** route (the encoder may place two diseases together because of a 2023 paper); test its size by comparing with an ontology-only encoder. Main route: that one.
- **Minimal test (~45 min, 4 GB GPU for embedding, then CPU).** (1) Embed ~15k disease names/definitions; (2) train a 2-layer projection with InfoNCE on pairs weighted by Jaccard of 19.04 -> 21.04 arrivals; (3) `score = sum_d sim(task, d) * context[d]` with top-k donors, mixed with `transfer_jaccard` by a weight that falls with the number of seeds; (4) dev split, stratified by seed count (<= 5, 6-20, > 20), against `transfer_jaccard` and `transfer_onto`.
- **Expected effect.** Overall +0.005 to +0.01 nuAP and AP; in the <= 5 seed stratum +0.02 to +0.03 nuAP. It does not touch stratum Z (the donor matrix is unchanged).
- **Kill rule.** No gain >= 0.005 nuAP over the better of `transfer_jaccard` / `transfer_onto` overall and < 0.015 in the <= 5 seed stratum.
- **Most likely failure.** `transfer_onto` already captures what text and ontology know, and the harness masks ontology relatives (TASKS), which removes exactly the donors this encoder would find.

### ML-9 — Evidence-trajectory hazard model over sub-threshold evidence streams
- **Mechanism.** Reformulate from "is the gene in the set" to "when does the pair cross the association threshold": a discrete-time hazard model per (disease, gene, evidence type), fed by the dated stream of weak evidence that already exists at the seed date (text-mining co-mentions with publication year, animal-model matches, expression, sub-threshold genetics) for the pair and for the pair's ontology neighbourhood. A small sequence model over yearly evidence counts per source learns acceleration, which a static score snapshot cannot express, and is trained on crossings between releases before the seed date.
- **p_typical:** 0.15
- **Data.** On disk: `/mnt/msadb/modet/downloads/ot_evidence/evidence_2104` (20 sources; the `europepmc` partition alone has 10,551,086 rows with `publicationYear`, `resourceScore`, `literature`, `textMiningSentences`; inspected), `evidence_2509` for the `forward` benchmark, 19.04 sets for training labels.
- **Leakage class:** temporal-clean on `temporal` (all inputs are the 21.04 evidence dump; training labels 19.04 -> 21.04). Main route: on `temporal` the panel removes "unknown (weak evidence)" genes from the ranking (TASKS, `exclude`), so the pairs with the strongest own-pair trajectories are not ranked at all; the signal must come from the gene's trajectory in *related* diseases, and that goes through the masked family rows. Check what fraction of dev targets has any non-family weak evidence before building anything.
- **Minimal test (~1.5 h, CPU).** (1) DuckDB over the `europepmc`, `phenodigm`, `expression_atlas` partitions: yearly counts and score sums per (disease, gene), 2010-2021; (2) aggregate each gene's trajectory over the task's 20 nearest non-family donors; (3) features = level, 3-year slope, recency, source diversity; gradient-boosted hazard model trained on 19.04 -> 21.04 crossings (trajectories truncated at 2019); (4) dev split with and without the trajectory features, plus the coverage check above.
- **Expected effect.** +0.005 to +0.015 nuAP, AP +0.01 (literature momentum favours studied genes, so AP gains more than nuAP). Little for stratum G (GWAS arrivals have no literature run-up), some for the ~40 % old-evidence arrivals of B5.
- **Kill rule.** Coverage: < 25 % of dev targets have any non-family weak-evidence trajectory, or slope/recency features add < +0.005 nuAP over the same model with level features only.
- **Most likely failure.** The exclusion of weak-evidence genes plus family masking leaves almost no trajectory signal, and what is left is gene popularity, which nuAP penalises (B6).

## Bets

- **Would bet on: ML-4 (release-pair power extrapolator).** It attacks the largest named stratum (57 % of new positives are GWAS-only, 16 % found, B4) with the one signal already measured to work (own-trait sub-threshold z, AUC ~0.8, B4), and turns it into a supervised problem with real paired data. Its weakness is coverage and the leakage bookkeeping, both of which are checkable in the first 30 minutes. Second choice: ML-1, because it is the only cheap idea that changes what happens to zero-support genes while leaving the working transfer machinery untouched.
- **Most underrated: ML-3 (dated supplement-table gene-set model).** It is a new information source rather than a new model on the old sources, it covers genes that no curated resource covers, and it can be date-filtered per paper, which most modern embeddings cannot. ML-2 is the most original formulation, but also the most likely to fail on the sim-to-real gap.

Dependencies worth knowing: ML-7 reuses ML-5's encoder; ML-3 can serve as the content space of ML-1 and ML-5; ML-6's LightGBM control doubles as a test of assumption A5 on its own.
